v1.0.4 (2026-07-07)

Fixed

If a destination doesn't have a Destination URL set, the fast package deploy guesses one from your FTP/SFTP host — and that guess can fail (e.g. an SSL certificate mismatch). Previously this failed the same way on every single sync. Now it stops trying after the first failure and quietly uploads file-by-file instead — set a Destination URL in that destination's settings to get the faster deploy back.
